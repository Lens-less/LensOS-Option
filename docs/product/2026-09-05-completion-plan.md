# 开源改造剩余工作与验收

用户已确认继续完成初次审查中剩余的全部本地改造。本文件在本轮代码修改前记录范围、清理计划和验收接口；承接首次使用迭代，不撤销已有改动。

## 完成标准

1. 核心分析拥有独立的、带类型的输入，主入口不再先构建 `research_report.v1`；兼容报告从同一份计算结果生成。旧入口继续可用。
2. 准入检查按行情、经济性、风险和运行状态分组，保留明确顺序及 `PASS / BLOCK / UNKNOWN`，不引入通用规则引擎。
3. 公开 OpenAPI 使用版本化静态契约，缺失、降级、正常及空数组状态不改变同版本 schema；发布数据在固定契约下验证，并有兼容性回归。
4. 缩小核心输入和前端报告的未知类型边界，非法数据在入口被拒绝。使用已有工具强化静态门禁，不擅自引入依赖。
5. 分析记录包含可核对的构建身份；离开 Git 的 wheel 仍能报告源码身份。发布标签、Python、Web、扩展及安装包版本必须一致。
6. 提供离线可复现研究案例、实际证据与缺失条件说明；不生成虚假历史胜率、模型校准或执行资格。
7. 完成初次审查余下的阅读体验与贡献体验：压缩手机辅助信息，突出结论和下一步；README 分流专题内容，提供范围清楚的贡献任务。
8. 完整验收覆盖 Python/Web、公开包隔离、最终安装包、窄屏与键盘流程、扩展首次连接；修复独立复核发现的问题后再交付。

## 清理顺序

- 先沿公共接口锁定固定样本的计算结果、条件顺序和原因码，再移动职责；不把旧大字典改名后继续作为核心输入。
- 复用现有规范化编码、验证器和领域记录；按真实职责提取，删除重复路径，避免空转适配层和新依赖。
- 核心、公开契约、构建溯源、前端和文档各自限定文件所有权；共享入口由对应所有者合并接线。
- 构建身份引入后，记录标识可以按设计变化；同一构建和固定输入应可重现，计算结论与门禁不能因职责拆分而变化。

## 已授权验收接口

- `build_analysis_record` / `AnalysisRun.evaluate` → 不可变分析记录与兼容投影。
- 公开 JSON 投影 → 固定 OpenAPI/schema → 合法和畸形跨语言样本。
- 源码/最终 wheel → 构建身份 → 分析 manifest；发布标签 → 多产物版本检查。
- 报告加载 → 主页、研究工具和扩展的用户可见状态；浏览器键盘与窄屏流程。
- 干净临时目录中的离线案例 → 固定输入摘要、状态、原因与证据缺口。

以上都是用户已要求完成的原审查验收范围。测试通过这些接口观察行为，不断言私有函数的组织方式。

## 持续边界

保持 `research_only=true`、`execution_allowed=false` 及证据不足时阻断。用户在本轮明确授权仅新增 mypy 开发依赖及其必要传递依赖，用于新核心接口的静态检查；运行包继续零依赖。不引入其他依赖，不执行真实交易、读取账户凭证、远端提交/推送、标签或发布。远端 CI 与生产基础设施的运行结果必须与本地验证区分。
