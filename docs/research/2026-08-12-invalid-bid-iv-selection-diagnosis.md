# `INVALID_BID_IV` 剔除潮诊断：选样尾部，而非全市场失效

> 核查日期：2026-08-12
> 数据范围：`artifacts/snapshots/btc-series/` 中截至 2026-08-12 的本地证据快照
> 结论用途：DS-1 诊断与 DS-2 裁决粒度调整的输入

## 结论

根因是 **(b) 选样策略**，不是所有研究窗口合约共同发生的市场性报价消失。

采集器声明的首选区间本来是 OTM call `1.0–1.3` 与 OTM put `0.7–1.0`，但旧实现
只用该区间决定排序优先级。每个到期日与 option type 达到最小配额后，预算补齐循环
仍会继续取首选区间之外的行。结果是反向 ITM 尾部（call moneyness `<1.0`、put
`>1.0`）被重新装入快照，而 `INVALID_BID_IV` 几乎只发生在那里。

证据很强：

- 基准通过日，首选带内 `INVALID_BID_IV = 0 / 527`；
- 问题期质量失败日，首选带内仍为 `0 / 318`；
- 问题期全部 `155 / 155` 个 `INVALID_BID_IV` 都在首选带外；
- 失败到期日中，首选带内坏报价仍全部为零，越线只由带外样本造成。

因此处置是把既有 moneyness 首选带从“排序提示”提升为非 fallback 路径的硬选样
边界。质量阈值 `max_bad_quote_ratio_per_expiry = 0.25` 保持不变；当上游不足以满足
最小配额而必须 fallback 时，仍允许保守采集，但在质量 verdict 附
`SELECTION_POLICY_FALLBACK_USED` advisory，不把 advisory 当成 pass/fail 条件。

## 方法

1. 每个 UTC 日取最后一份带 `captured_at` 的快照，避免手动重跑让单日重复加权。
2. 基准组取 2026-07-26 至 2026-08-03 中通过整份质量门禁的 8 个日期：
   `07-26/27/28/29/30`、`08-01/02/03`；07-31 因一个到期日越线不进入基准。
3. 问题组取 2026-08-04 至 08-12 中整份质量门禁失败的日期。08-07 是无报价的
   传输失败，分桶分母为零；报价型失败实际为 `08-04/05/08/09/10/12`。08-11
   是 `EXCHANGE_FULL_LOCK`，不与报价问题混合；08-06 正常通过。
4. 用生产代码 `normalize_market_snapshot` 重新计算每行 `quality_flags`，moneyness
   取 `strike / option forward`，按 option type 与固定桶统计 `INVALID_BID_IV`。
5. “首选带”严格按仓库已有策略常量定义，不按结果反向选择区间。

这些日期同时都存在其他通过门禁的到期日，故旧的整份快照裁决把一个选样尾部问题
放大成所有 cohort 的共同数据损失。DS-2 的按到期日隔离仍然必要：选样修复阻止未来
重现，隔离修复则消除任何单到期日缺陷对健康证据单元的连坐。

## 验收约束

- 非 fallback 选样不会为补满 ticker 预算重新引入 call `<1.0` 或 put `>1.0`；
- 每个被选择的到期日两侧仍达到既有最小配额；
- fallback 保持显式、可观测，且 advisory 不改变质量 pass/fail；
- 所有质量阈值原值保留。
